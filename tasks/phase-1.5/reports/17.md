# p1.5-17 — The runner on the host

The whole agent runs on a workstation now. `JobRunner` and `AgentLoop` are
driven exactly as the board drives them — `claimAndRun()` and `loop()` — against
a stock repeater behind `IMesh`, a scripted meshmaster.dk behind `IUplink` and a
clock that only moves when a test says so, and **all thirteen job types, the
login sequence, the rotation probe, the ACL restore, the airtime gate, the
offline buffer, the backoff and the reboot guard are walked end to end in 935
milliseconds**. Nothing sleeps: `IPlatform::delayMs` *is* the passage of time, so
the twenty-second minimum gap is twenty thousand turns of arithmetic and a
config read that is eleven minutes of airtime on the board is a few
milliseconds here.

This is the host harness of `tasks/phase-1.1/08-the-host-harness.md`, built the
way the library allows: three fakes in `test/support/`, two suites
(`test/test_runner`, 45 cases; `test/test_loop`, 14), and no `[env:host]`, no
second `JobRunner`, no `HostMesh`. **`FakeMesh` is a second reading of the
firmware source** — `examples/simple_repeater/MyMesh.cpp` and
`src/helpers/CommonCLI.cpp` at the pin — and every answer it gives cites a
transcribed fixture or a function with its file and line range, which a test
walks against the manifest and against the pinned checkout on disk.

**The Heltec does the same thing.** All 337 native cases pass — the 278 of
`master` with no assertion changed, plus the 59 of the two new suites — both
boards build with `-Werror`, RAM is byte for byte `master`'s and flash is **96
bytes smaller** on the V3 and 84 on the V4, all of it the one virtual method this
task removed from `IMesh` (the follow-up task 15 left).

`spec/EXIT-NODES.md` §5, §6 and §7 were read in full from `twinoak/meshmaster.dk`
at today's `origin/master`, `6c0d636` (the local clone is on another task's
branch; the file is identical there). Proposal 03's *What it costs here* and
`tasks/phase-1.1/08-the-host-harness.md` are what the deliverables are measured
against. The pinned MeshCore was read on disk at
`.pio/libdeps/heltec_v3/MeshCore`, `d9296435`.

## The two older fakes are kept, and here is the sentence

`test_config_apply`'s `FakeRepeater` and `test_rotation_probe`'s
`ScriptedRepeater` are **not** repeaters behind `IMesh` and `FakeMesh` does not
replace them: they implement `mm::ApplyExchange` and `mm::LoginExchange`, the
seams one level *above* the mesh through which the apply engine and the login
sequence ask for *a line on the air* and *a login* without knowing what a packet
is. A script at that level says "this line was refused, this one was eaten, the
lease ran out here" in one word, which is how those two suites walk every branch
of the policy; doing the same through `FakeMesh` would mean arranging
radio-level silences to provoke a policy-level answer, and would be a test of
the arrangement. So there is no duplicated repeater behaviour across three
fakes: there is **one** repeater and **two** exchange scripts, and
`test_runner` is where they meet — the apply's lines really go to a repeater
that really answers them, and the rotation probe's four paths are one scenario
there as well. `docs/host.md` says this where a reader will look for it.

## Deviations from the spec or the task

- **`test/support/` is header-only, and that is how it is "compiled into the
  suites that need it".** PlatformIO compiles a test directory's own sources and
  the files at the root of `test/`, and nothing else: a `test/support/*.cpp`
  would be compiled into *no* suite (`platformio/builder/tools/piotest.py`'s
  `PIOTEST_SRC_FILTER` is `+<$PIOTEST_RUNNING_NAME/>` plus `+<*.cpp>` at the
  root, and `platformio/test/helpers.py` collects only directories named
  `test_*` as suites). Putting the fakes at the root of `test/` would compile
  them into all twenty-two suites instead. Header-only is the one shape that is
  built exactly where it is included, and `$PROJECT_TEST_DIR` is already on
  every suite's include path, so `#include <support/FakeMesh.h>` needs no
  change to `platformio.ini` at all.
- **`IMesh::uniqueTime()` is dropped**, which the task did not ask for and this
  pile's `FOLLOWUPS.md` did ("drop it from `IMesh` in 16 or 17"); 16's report
  left it here, where the fakes that implement the interface are written and the
  cut is free. `IMesh.h` carries the reason in its place, `AgentMesh` keeps the
  method as the board's own (its `sendCli` draws from it), and `test_seams` has
  one new assertion so it cannot come back unnoticed. This is the only change of
  this task that moves a byte of the board image: −96 and −84.
- **The contract fixtures' sample passwords are longer than the firmware
  keeps**, which the fakes found at once: `"admin-password-sample"` is
  twenty-one characters and `NodePrefs` holds `char password[16]`, so a login
  carrying it is silence on both ends. The fake therefore cuts a password to
  fifteen bytes in `setAdminPassword`/`setGuestPassword` as the firmware does,
  and the tests use ten-character passwords so that nothing passes by accident
  through a truncation. **The firmware is right and says so** (`loginMaterialFor`
  logs the cut); what is missing is a refusal at meshmaster.dk's credentials
  *form*, which is this pile's new `FOLLOWUPS.md` item for the other repository.
- **The heartbeat half of the extension's deliverable is in `test_loop`,** not
  `test_runner`. The task lists "its types in the heartbeat" under
  `test_runner`'s bullet, and the heartbeat is `AgentLoop`'s: asserting it from
  `test_runner` would have meant a second copy of `test_loop`'s whole setup for
  one line. `AnExtensionsTypesFollowTheThirteenInTheHeartbeat` is the test; the
  claim, the run, the `data` and the `unsupported` are in `test_runner` as asked.
- **`extendLease` and `postProgress` are driven through the seam and not through
  a job**, because nothing in the library calls them (15's own deviation): the
  test posts them at `IUplink` and holds what the fake captured against
  `ExtendRequest.json` and `ProgressReport.json` byte for byte, and
  `A409OnAnExtendIsNotTheLeaseHolderAndIsFalse` holds the 409. The first job
  type that needs a lease extension is the one that will drive them for real.
- **A result is held against the *shape* of its contract fixture**, not byte for
  byte: `test_job_results` already holds every writer to its fixture byte for
  byte for one sample each, and what a *run* can add is that the members
  ContractsJson writes are the ones that come out, in its order, with the
  optional ones this run had nothing to say about left out — which is what the
  records' nulls mean. `fake::followsShapeOf` is that check, and it refuses a
  member the fixture has not got as well as one out of order.
- **For the other repository**: the stored-password bound above. Nothing of
  `EXIT-NODES.md` §5–§7 disagreed with the firmware once my own expectations were
  corrected — three of my first assertions were wrong and the code was right (a
  discover with no path makes **one** login and not two; the ACL a config read
  reports lists our own key at **admin**, because the read's own login put it
  there and the request comes before the restore; and a session is cached under
  the **repeater's** key, not the exit node's).

## Decisions taken without asking

- **The citation rule is a manifest in `FakeMesh.h` and a test that walks it
  both ways.** The task asks for "the citation header, as `test_contract_fixtures`
  checks its manifest", and a fixture's citation is one `# fw ` line per file; a
  fake gives many answers in one file, so the manifest is one line per *answer*
  (`// answer: <name>  cite: …`) and the body marks each answer where it is
  produced (`// answer: <name>`). The test requires the two sets to be equal, so
  a citation for an answer nobody gives fails as loudly as an answer nobody
  cited.
- **The `fw` half of the check is deep only when MeshCore is on disk.** CI's
  native job installs the host dependencies alone and has no
  `.pio/libdeps/heltec_v3/MeshCore`, so the *form* of every citation (the tag
  and the commit against `platformio.ini`, a file, a line range, a function) is
  always checked and the *source* (the file is there, is long enough, defines
  that function at or above the lines cited) is checked whenever a board has been
  built. A session and a bump both have it; CI would have to build a board to,
  and that is the `build` job's minute, not this one's.
- **A citation names a range inside a function and the check looks for the
  definition at or above it.** The fixtures cite whole functions
  (`MyMesh.cpp:90-145 handleLoginReq`); a fake's answers are sub-ranges of one
  (`:100-128` is the password branch), and requiring the name *on* those lines
  would have forced every citation back to the whole function and lost the
  precision. What catches a bump is the same either way: a function renamed or
  moved is no longer defined above the lines claimed.
- **The fake clock advances on `delayMs`, by at least one millisecond.** A
  zero-millisecond delay is a yield and some microseconds on a board, and a
  library loop that waited on a clock that never moved would not end.
- **`rebootForHealth` records and throws.** The method is `[[noreturn]]`, so it
  cannot return, and a test that watched the guard fire must not fall through
  into the rest of the loop. `FakePlatform::Reboot` carries the reason; the test
  catches it and nothing restarts.
- **Faults are "the next *n* calls" and not a scripted transcript.** `beSilent(2)`,
  `replyWithTheWrongTag(1)`, `refuseTheNextLogin(1)`, `failWith(Fault, n)` — a
  test says what goes wrong and how often, and the fake decides where, which is
  what a radio does. `FakeUplink::failResults` is the one per-call knob, because
  the claim that hands a job over has to be answered for the job to run at all
  and the offline buffer is exactly what a server that went away *under* a
  running job fills.
- **The reply a repeater sends is zero-padded to the cipher block** by default,
  because that is what the air does (`Utils::encrypt`, and
  `binary-response-telemetry-padded.hex` is a capture of it) and every parser
  the library has tolerates it. `setPadding(false)` is there for a test that
  wants the exact length.
- **A job begun for a key that is not this repeater's reaches nobody.** There is
  one repeater behind the fake; addressing another is silence from everything,
  which is the honest answer and a useful one.
- **The claim is built as JSON and parsed by `mm::parseClaimResponse`.** The
  fake server writes a `ClaimResponse` envelope from `support/Jobs.h` (which is
  `ClaimedJob.json`'s shape) and hands it to the firmware's own parser into the
  runner's own buffer — so no test invents a `ClaimedJob` field by field, the
  parser is exercised by every scenario, and the credential can be read back
  from the buffer the runner was given.
- **The keys in `support/Jobs.h` are whole ones.** `ClaimedJob.json`'s
  `publicKey` is `a1b2`, four hex characters, which is all the server's own
  round-trip test needed and which `AgentMesh::beginJob` refuses — a key that is
  not 64 hex characters is not an identity to address. The builder's default is
  a whole key and the file says why.
- **`out/native.sh`** is the runbook's container line as one script, so the
  evidence in `out/` can be reproduced with one `docker run`. It is in `out/`,
  which is git-ignored, and nothing depends on it.
