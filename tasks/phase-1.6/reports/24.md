meshmaster.dk's pile 4.15 moved the shared serializer to .NET's **relaxed** JSON
encoder (its task 129), and this firmware's one writer copied the default
encoder's escaping byte for byte — so its fixture tests were about to compare
against bytes it no longer makes. This task moves the writer, syncs the fixtures,
takes the two new samples into the tests they were made for, writes `docs/library.md`
§2 for a private repository, and closes `v0.3.0`.

**The Heltec's behaviour changes only by the bytes the rule saves.** RAM ±0 on
both boards; flash **+244** (V3) and **+296** (V4), all of it `.flash.text`, named
symbol by symbol below. Nothing it prints changed, no console line moved and
`docs/console.md` did not move.

`pio test -e native`: **387 cases in 23 suites, all passing** (376 in 22 before —
twelve new in one new suite, one retired with the rule it held). Both boards
SUCCESS with `-Werror`; 20's five-configuration host matrix, the component check
and `-Verify` are green.

## What the new rule saves on the wire

The point of the dialect from this end. Per character, in any string the board
sends: a `>`, a `'` or a `+` costs **1 byte instead of 6**, a Danish letter
**2 instead of 6**, an em dash **3 instead of 6**, a section sign **2 instead
of 6**. In whole bodies:

| | before | after |
|---|---|---|
| `ConfigReadResult.json` itself — one `>` in a CLI reply | 161 | **156** (measured: the fixture's own bytes before and after the sync) |
| a `cli` result, the prompt and a Danish name: `{"command":"get name","reply":"> Grenå Chimney #1",…}` | 109 | **100** |
| a `config.read` whose name is Danish and whose ACL was silent (an em dash and a section sign in one raw line) | 299 | **288** |
| any result carrying a version with build metadata (`0.3.0+abc1234`) | 36 | **31** |

So a typical CLI reply saves **5 bytes** for its prompt and **4 more** for each
Danish letter in the repeater's name — nine bytes a result for the two together,
on a board whose wake budget is counted in bytes (p1.6-21). The three figures
that are not a fixture's own bytes are arithmetic over the two rules, with the
rule itself proven against `JsonEscaping.json`.

## Decisions taken without asking

- **The escaping suite is a file of its own**, `test/test_json_escaping/`, and
  the one case that held the old rule (`JsonWriterEscaping.TheBytesAreSystem
  TextJsonsForTheSameValue`, in `test_config_read`) is gone with it. The rule has
  eight clauses and a fixture of its own now; a suite named after it makes
  `pio test`'s own output say which clause failed, where before the escaping was
  a footnote in the suite of the config read. `test_config_read` keeps the
  assertions that are about *its* fixture's bytes, and its header points at the
  new suite.
- **The enumerable half of clause 7 is implemented; the table-driven half is
  not.** `escapedAboveAscii()` is seven range checks — the C1 controls and NBSP,
  the space separators, U+2028/9, private use, the non-characters, the BOM, the
  top two code points — which is every part of the clause that is a range. The
  alternative, implementing none of the clause and documenting the whole of it as
  a difference, would have been cheaper by about 100 bytes of flash and would
  have made the writer differ from the server for characters it is perfectly able
  to recognise. A consumer copying this writer gets the rule, minus one clause it
  is honest about.
- **An overlong encoding of an ASCII byte goes through `escape()`.** `C0 80`
  decodes to U+0000 and `C0 AF` to `/`; routing a decoded code point below 0x80
  back through the ASCII path means such a sequence is escaped as the character it
  encodes rather than as a code point above ASCII. No input the firmware sees is
  overlong; it costs nothing and it means there is no path through `string()` that
  writes a raw control byte.
- **The two heartbeat fixtures are held to each other, not one to a cut of the
  other.** The expectation for this board's heartbeat is a whole file. The second
  pair of assertions compares the two *files*, which is the only way this end can
  notice that meshmaster.dk changed one sample and not the other — the thing the
  1.5 review was worried about when it called the cut *the only anchor until
  meshmaster.dk adds a second heartbeat fixture*.
- **`test_loop`'s three long passwords stay where they are.** They were described
  as *the contract fixtures' three samples* and are not that any more, so the
  comment is rewritten: they are the test's own, longer than a repeater keeps on
  purpose, because the rail that test holds is that **neither the whole secret nor
  the cut prefix** reaches the kept image. Shortening them to the new samples
  would have removed the `substr(0, kMaxPasswordLen)` half of that rail.
- **`CHANGELOG.md`'s heading loses *(unreleased)* and gains a title**, the shape
  `## v0.2.0 — the agent core as a library` had at its own tag. The four questions
  at the top of the section are answered for the whole of it, as 23 wrote them:
  the fixtures' answer is now the long one and says **this is the dangerous one**,
  with what a consumer's writer has to do and which fixture to do it against. The
  tag itself is Thomas's.
- **`tests/fixtures/contracts/README.md` gained a paragraph** about the two files
  in that directory that are not envelopes — a test-only record and a second
  sample of a record that already has a file — because a reader of the directory
  cannot tell either from its name.
- **`docs/library.md` §2 is two numbered sub-sections**, §2.1 the checked copy and
  §2.2 the token, rather than one paragraph each: a consumer reads one of the two
  and skips the other.

## What `docs/library.md` §2 now says, and where it came from

The task asked for *what the Walter did*, not for an invention, so §2.1 is read
off that repository at its `task/p4-01-the-library-arrives` branch:
`tools/sync-agent-core.ps1`'s own header and `docs/upstream.md`'s *The one
secret*. Two trees come across — `components/agent-core/` (this library with the
prefix stripped, the ESP-IDF component unedited) and `host_test/agent-core/`
(`test/support/`, `test/test_runner/`, `test/test_loop/`, both fixture
directories and `platformio.ini`, **at this repository's own paths**, because
`test_runner`'s `Citations` case reads those paths relative to a `PROJECT_DIR` it
is handed) — each with a `MANIFEST.txt` naming the tag and the commit and holding
a SHA-256 per file, and `-Verify` runs in their CI before anything is built,
needing no network and no clone of this repository. §2.2 is the alternative: a
fine-grained token with *Contents: read* on this repository and nothing else,
`AGENT_CORE_READ_TOKEN` as an Actions secret, **in the secret store and nowhere
else** — not in `idf_component.yml`, not in `platformio.ini`, not in a lock file,
not in a checked-in `.netrc`, and not in a log line, because a clone URL with a
token in it is printed by every verbose git. And the third way out, which is not
a consumer's to take: this repository made public, after which the two dependency
lines in §2 work as written.

## Not verified here (and why)

Nothing the Heltec *does* changed, so 1.5's, 20's, 21's and 22's bench lists stand
as they were. What this task leaves unverified is the dialect's other end:

1. **A board's output read by the real server** — the next bench walk, with one
   `frame tx` line and one job result's **raw body** pasted into its report. That
   body is what this task is about: a `cli` reply that starts `> ` and a repeater
   name with a Danish letter in it should arrive at meshmaster.dk as themselves,
   and the job's page should show them unescaped. A session can build the bytes
   and compare them with a fixture; only a board and a server can show that the
   server's reader likes them. Flash `v0.3.0` for it (AarhusC and Grindsted are
   still on `v0.1.3`; 1.4's four guest-door checks go on the same flash).
2. **`v0.3.0` is not tagged.** `CHANGELOG.md`'s section is closed and the three
   manifests say `0.3.0` (p1.6-23), but the tag is a person pushing it and the
   release workflow makes the images. The Walter's p4-01 stops rather than pin an
   untagged commit, so that repository's pile waits on it.
3. **The Walter against this dialect** (its p4-01 and p4-02, after the tag): its
   own writer is written against `JsonEscaping.json` from the start, and its copy
   of `tests/fixtures/contracts/` comes across at `v0.3.0` with the new bytes in
   it. What only that build can answer is that a second writer held to the same
   file agrees with this one.
4. **The unassigned-code-point difference against the real server.** Held here by
   a parse (ArduinoJson reads our bytes and .NET's as one string), which is the
   test the task asked for; what no test here can do is put such a character in
   front of `System.Text.Json`. Nothing on the board's inputs produces one — a
   repeater name comes out of MeshCore's advert bytes and a CLI reply out of its
   console — so this is a difference on paper rather than one on the wire.
