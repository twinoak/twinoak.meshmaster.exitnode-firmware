# p1.18-66 — The receiver is put back on a timer

MeshCore already has what 19 November needed, and it was off. `Dispatcher::loop()` arms a timer
from `getAGCResetInterval()` and calls the radio's own `resetAGC()` when it runs out — and
`Dispatcher::getAGCResetInterval()` answers 0, *disabled*, unless an application overrides it.
This firmware never did. It does now, with one function's number behind one setting.

**What is new, as a person sees it.** `agc.reset.interval`, whole seconds, 4 unless set, 0 to
3600, in force the moment it is set. `status`' `radio` line ends `receiver reset every 4 s` — or
`receiver never reset` at 0 — and its `frames` line says `noise floor being measured` instead of
a `0 dBm` for the moment after a reset while the floor is sampled again. The observer's status
message leaves `noise_floor` out for that same moment. Nothing else of the radio moved.

**Where it lives.** `src/mesh/Receiver.h` and `.cpp`: the interval in seconds, the same interval
in milliseconds for the dispatcher, the two phrases `status` prints, and the one question *is
this floor a reading?* that `status` and `src/observer/Dialect.cpp` both ask. Host-portable, so
`test/test_receiver` holds every word of it, and the citations it rests on are held against the
pinned MeshCore on disk — `getAGCResetInterval`'s default of 0, the timer in `Dispatcher::loop()`,
`futureMillis(int)` (which is why the hook is milliseconds), `resetAGC()`'s `_noise_floor = 0`
and its refusal to run mid-receive, and the companion's own override. `AgentMesh.h` is one line:
`int getAGCResetInterval() const override { return agcResetIntervalMs(); }`.

## Deviations from the spec or the task

- None of substance. The spec here is the pinned MeshCore source, read on disk at
  `81dbae59`; every line the task cites is where it said it was, and
  `test_receiver`'s `Upstream` test now holds the five that matter.
- One thing the task did not say and the repeater's own CLI does: a repeater rounds
  `set agc.reset.interval <secs>` to a multiple of four, because it stores the value in units of
  four seconds (`CommonCLI.h:51`, `122-123`) and says *OK - interval rounded to N*. This firmware
  keeps the seconds as they were typed and does not round them — nothing here is stored in a
  repeater's format — and its range is the task's 0..3600 rather than the repeater's 0..1020. The
  name, the unit and the default of four are the repeaters' as the task asked.
- The task's line numbers for `docs/console.md` (~62-66, ~88, ~103) are from an earlier state of
  that file; the table, the *set takes effect at once* paragraph and the status sections are all
  there, at other lines.

## Decisions taken without asking

- **The key sits after `radio.tx` in `get`'s order**, so a person reading `get` sees the radio's
  settings together. Its own prefix is its own branch of `onSettingChanged`.
- **`applyAgcSettings()` is a function of its own**, not a line inside `applyRadioSettings()`:
  deliverable 5 is that nothing else of the radio changes, and the two are then separately
  readable. It logs one line — `radio: receiver reset every 4 s` — at boot and on every change,
  so the bench walk is reading.
- **The words.** `receiver reset every 4 s` / `receiver never reset` on the `radio` line;
  `noise floor being measured` where the number usually is on the `frames` line. The task fixed
  *every 4 s* and *never*; the rest is this firmware's own plain English.
- **The *is this floor a reading?* rule lives in `src/mesh/Receiver.h`** and is asked by the two
  printers rather than by the producer. `src/observer/Observer.cpp` and `fillBoardStats` are
  board-only and no host test can reach them, while `src/observer/Dialect.cpp` is host-built: one
  file holds the rule, two places ask it, and both are under test. `fillBoardStats` hands the raw
  figure on unchanged.
- **A 0 floor publishes no `stats` object at all**, rather than an empty one: the rule went into
  `Dialect.cpp`'s `anyStat` as well as into the member's write. A `"stats":{}` nobody had seen
  before would have been a new shape on the wire for the observer's brokers.
- **A value outside 0..3600 is clamped, not refused, where it is used.** The console refuses one;
  but a number that reached NVS before this range existed should not leave the timer off by
  accident, so `setAgcResetSeconds` clamps. The module's own default before anything is pushed is
  4 s for the same reason: a board whose settings could not be read is a board with the timer on.
- **0 is kept as 0 all the way to the hook**, because `getAGCResetInterval() > 0` is MeshCore's
  own test for *never*.
- **No heartbeat member and no contract change**, as the task asks; `tests/fixtures/contracts/`
  is untouched and `CHANGELOG.md` gets no line (nothing of `lib/agent-core`'s interfaces, caps or
  fixtures moved). `release-notes/unreleased/66.md` is the one line a person will notice.
- **`docs/upstream.md` gets a row** for the four MeshCore places this now rests on, because that
  page is what a pin bump re-reads and `test_receiver` is what would go red.

## Not verified here (and why)

A session cannot flash a board or hear a radio. With a V3 or V4 on the bench, after the flash:

- ⚠ **`status`.** The `radio` line ends `receiver reset every 4 s`. The `frames` line's floor is a
  number — `noise floor -112 dBm` or thereabouts — and shows `noise floor being measured` only
  for a moment now and then; it should be a number again by the next `status`. `frames rx` goes on
  rising while this happens: that is the whole point, and a `rx` that stopped climbing after the
  flash would be this task having made things worse.
- ⚠ **The boot log** says `radio: receiver reset every 4 s` on the line after the radio's
  parameters.
- ⚠ **`set agc.reset.interval 10`** → `ok agc.reset.interval`, the log says
  `radio: receiver reset every 10 s`, and `status` agrees — with no reboot. **`set
  agc.reset.interval 0`** → `receiver never reset`, and the floor stops being *being measured*.
  **`set agc.reset.interval 3601`** → `error: agc.reset.interval: out of range, 0..3600`. Put it
  back to 4 (or `erase confirm` on a bench board).
- ⚠ **The observer**, if a slot is on: a status message published in the moment after a reset has
  no `noise_floor` member, and the ones either side of it do. Readable on the broker, not here.
- ⚠ **A week of nights on Risskov with nothing like 19 November.** The state cannot be brought on
  at will and nothing the server keeps says what an exit node's receiver did, so this is the only
  evidence there will be. Four seconds is Thomas's number to change if a reset turns out to cost
  a reply that was on its way (`FOLLOWUPS.md`).
- ⚠ **That the AGC was the cause is still not shown.** This is what upstream has for the symptom
  and what the repeaters run with; it is not a diagnosis.
