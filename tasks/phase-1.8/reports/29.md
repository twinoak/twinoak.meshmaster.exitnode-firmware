`if: runner.environment == 'github-hosted'` now, with the comment
meshmaster.dk's `70b73ad` wrote for the same change. `release.yml`'s keeps no

starts. `setup-python` and `pip install "platformio==6.1.19"` are untouched in

The guard is [`tools/check-runners.py`](../../../tools/check-runners.py) and the

installed and before anything is built, because it is about this directory and
not about the firmware — and it is Python 3 and the standard library, because a
self-hosted runner has no PyYAML.

## Decisions taken without asking

- **The guard reads the YAML itself rather than installing PyYAML.** It runs
  before `pip install platformio`, and a self-hosted runner's Python — the one
  `setup-python` puts in the tool cache — has no YAML parser. So the reader
  understands the slice of YAML these three files are written in (a `jobs:`
  mapping at column 0, a job two spaces in, its `runs-on` two further) and is
  block-scalar aware, so a `run: |` body — `release.yml` has a heredoc inside
  one — cannot be misread as a job. **A file it cannot read is a failure, not a
  pass**: a workflow with no job found, a job with no `runs-on`, and a
  `runs-on` that is a `${{ }}` expression are each an error naming the file,
  the line and the job. `--self-test` is seven planted workflows it must refuse
  and one it must accept.
- **The guard lives in `ci.yml`'s `native` job, not in a job of its own.** A
  fourth job would queue behind the three on a host with five runners shared
  with meshmaster.dk, for a check that takes under a second. It is that job's
  first step after `setup-python`, so it fails before the minute of relinking.
  The cost is that it does not run when the `build` matrix is the only job that
  fails — which is not a case the guard is about.
- **`release.yml` is identified by its file name.** "Everything that ships" is
  one file today, and a rule written as a list of file names is a rule a
  reviewer can read; a second shipping workflow adds one line to `SHIPS` in
  that script and nothing else. The alternative — a marker comment inside each
  workflow — puts the rule in as many places as there are workflows, which is
  what the task asked it not to be.
- **A hosted `runs-on` is checked by prefix, not only by the absence of
  `self-hosted`.** `ubuntu-`, `windows-`, `macos-`: so `ubunut-latest` is
  caught here rather than by a queued job that never starts. (That is one of
  the self-test's seven.)
- **`upstream.yml`'s two files outside the workspace moved to `$RUNNER_TEMP`.**
  It cloned MeshCore to `/tmp/meshcore` and wrote the pull request body to
  `/tmp/body.md`. A GitHub-hosted runner is new every job, so both were safe
  there; a runner at home keeps its disk, and `git clone` into a `/tmp/meshcore`
  a previous run left behind fails outright. `$RUNNER_TEMP` is per-job and the
  runner empties it when the job starts. This is the only thing deliverable 4
  found, and it was fixed in the job.
- **Nothing else needed fixing for a shared host.** No job of this repository
  binds a host port (nothing in it serves anything: there is no compose stack,
  no database and no browser, which is what `35a5d2a` was about in
  meshmaster.dk), nothing is started that must be taken down `if: always()`,
  and the only writes outside a workspace are `~/.platformio`, `~/.cache/pip`
  and `setup-python`'s tool cache — the runner's own home, which is the point
  of leaving the caches off. `actions/checkout`'s `clean` is the default and
  `git clean -ffdx` takes ignored files with it, so the last branch's `.pio/`
  is gone before a build starts. <!--CLEAN-->
- **The words went into the README as a section of its own, *Where CI runs*,**
  before *Keeping up with MeshCore*: the workflow table and where each one
  runs, why the first two are at home and why the release is not, why the
  caches are skipped at home and what is not skipped, the guard, and what a
  runner must have. *Building it* and the release paragraph under *Flashing it*
  point at it, and `docs/upstream.md`'s tier one gained a paragraph saying that
  `upstream.yml` runs at home and what that means for anyone editing it (no
  host port; `$RUNNER_TEMP`, not `/tmp`).
