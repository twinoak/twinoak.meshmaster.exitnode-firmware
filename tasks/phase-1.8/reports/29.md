# p1.8-29 — Built away, because it is public

CI runs on GitHub's runners, every job of every workflow, and the guard in
`ci.yml` refuses a `self-hosted` label anywhere in `.github/workflows/`.

The first session of this task did what Thomas asked on 31 October — *all CI is
to run on our new Unraid runners* — and its jobs then sat queued for 28 minutes
with no runner while the same runners took meshmaster.dk's within two seconds.
The runner group is set to *All repositories*, but **this repository is public**
and meshmaster.dk and the repeater firmware are private: a runner group reaches
a public repository only when *Allow public repositories* is ticked. It is not
ticked, and this task's conclusion is that it should stay that way, because the
premise of the move does not hold here:

- **Running here costs nothing.** [Actions on standard GitHub-hosted runners are
  free in a public repository](https://docs.github.com/en/actions/concepts/billing-and-usage)
  — *"GitHub Actions usage is free for standard GitHub-hosted runners in public
  repositories, and for self-hosted runners"* — so this repository has never
  spent a credit. The minutes that got out of hand are the private
  repositories', which is exactly where moving home paid.
- **On a public repository a self-hosted runner runs a stranger's code.** Anyone
  may fork and open a pull request, a pull request can change a workflow file,
  and it would then run on the Unraid host with its docker socket, its LAN and
  its Tailscale. GitHub's own words:
  [*"Self-hosted runners should almost never be used for public repositories on
  GitHub, because any user can open pull requests against the repository and
  compromise the environment."*](https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions#hardening-for-self-hosted-runners)

So the guard the first session wrote is turned around, and it is one rule for
every file rather than two halves: `release.yml` is no longer an exception,
because the reason now covers it as well.

| Workflow | First session (`dc0861b`) | Now |
|---|---|---|
| `ci.yml`, `build (heltec_v3)` / `build (heltec_v4)` | `[self-hosted, unraid]` | `ubuntu-latest` |
| `ci.yml`, `native tests` | `[self-hosted, unraid]` | `ubuntu-latest` |
| `upstream.yml`, `bump` | `[self-hosted, unraid]` | `ubuntu-latest` |
| `release.yml`, all three jobs | `ubuntu-latest`, *what ships stays away* | `ubuntu-latest`, *a public repository* |

`ci.yml`'s diff against `master` is now the guard step and the words and nothing
else: both cache steps have lost their `if: runner.environment ==
'github-hosted'` condition, because every job runs on a machine with nothing on
disk. `release.yml`'s diff is seven comment lines. `upstream.yml` keeps the one
real find of the first session — `$RUNNER_TEMP` instead of a fixed `/tmp` path
for its blobless clone and its pull request body, which is right on any runner,
because `$RUNNER_TEMP` is per-job and emptied when the job starts.

**Four commits on this branch, two sessions.** `dc0861b` and `234c629` are the
first session's and are left where they are: `dc0861b` is the move home, and the
README now points at it by name as the change to take back if this repository is
ever made private. `3833f14` is the rework, `456bb2a`/`5c24a26` are the scratch
commit of criterion 2 and its revert, and `1681c6a` is one thing the rework

## Decisions taken without asking

- **The rule is "every job runs on a GitHub-hosted runner", not "no job carries
  the `self-hosted` label".** The task asks for the second; the first is the
  same refusal plus one more, and the extra one matters. GitHub adds
  `self-hosted` to a self-hosted runner's labels of its own accord, but a
  workflow may *address* that runner by any of its labels — `runs-on: unraid`
  reaches the Unraid containers with no `self-hosted` written anywhere. A guard
  that looks only for the word would pass it. So the check is: exactly one
  label, beginning `ubuntu-`, `windows-` or `macos-`. A `self-hosted` label gets
  the named sentence; anything else that is not a hosted label gets a message
  saying that if it is a self-hosted runner under its own label the rule is the
  same. The typo case the first session built (`ubunut-latest`, which would
  queue for ever) falls out of the same check and is kept.
- **The reason is one sentence, as deliverable 4 asks, and it is one string in
  one place.** `REASON` in `tools/check-runners.py`: *"a public repository; a
  fork's pull request would run on the host. Every job here runs on a
  GitHub-hosted runner, which is free for a public repository."* Both refusal
  messages end with it, so the two halves of the why travel together.
- **`SHIPS` is gone.** One rule, every file, and `release.yml` identified by
  nothing. The self-test keeps a *"release.yml at home, which is no different"*
  case so that the day someone reintroduces an exception, a test says what
  changed.
- **The `::error::` lines of the self-test were turned off** (`1681c6a`).
  `::error::` is a workflow command, so GitHub turns each one into a *failure
  annotation* against the file and line it names — and the self-test's planted
  files are called `ci.yml` and `release.yml` like the real ones. Every green
  run therefore carried **nine failure annotations pointing at lines of this
  repository that are not wrong** (`.github/workflows/ci.yml:4, job build` and
  the rest; run `41191528050` has them, and the first session's version had
  seven of the same). `check()` now takes `annotate=False` for the self-test and
  prints `  refused: …`; a real refusal still annotates, which is the point of
  it. The final run's annotations are GitHub's own two and nothing else.
- **The guard stays in `ci.yml`'s `native` job**, as deliverable 4 says, and the
  cost of that is unchanged from the first session: it does not run when the
  `build` matrix is the only job that fails, which is not a case it is about.
- **The README's *Where CI runs* was rewritten rather than edited.** It is the
  one page for the decision, so it carries both halves of the reason with the
  two GitHub links, the table of three workflows, the guard, and — deliverable 5
  — the named way back: `dc0861b` *CI runs at home, the release does not*, what
  it does to each file, and the honest note that it is **not** a clean
  `git revert`, because the commits after it on this same branch edit the same
  lines. The eight-item list of what a runner must have stays, now explicitly
  for the day that move is taken back: `g++` and `cmake` are the two a
  self-hosted image would not have, and nothing in a job installs them.
- **The native suite was not re-run in the container for `1681c6a`.** That
  commit changes one `print` path in `tools/check-runners.py` and nothing the
  firmware or the host tests compile; the 466 cases ran in CI on that exact
  commit instead, which is the stronger evidence of the two.
