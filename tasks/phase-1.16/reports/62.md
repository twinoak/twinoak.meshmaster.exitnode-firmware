## Decisions taken without asking

- **The third `WaitingFixtures` test moves suite rather than dying.** Deliverable 4 asks for
  the two relations to be held *in the copied tree*; that is no longer a statement about
  anything waiting, so the test is `ContractFixtures`' now. The test count does not move and
  the deliverable is met by a test rather than by the two suites that read those files
  incidentally.
- **`kWaiting` stays, as an empty `std::vector<Waiting>`.** Deliverable 3 keeps the place for
  the next one, and the two tripwires need a list to hold a file against. Empty, they pass on
  an empty directory and fire the moment a file appears without its line. The README's
  *Adding one* section is the five steps, and it names `kWaiting` and `AHEAD_FIXTURES_DIR`.
- **The per-suite waiting readers go; the define stays.** `AHEAD_FIXTURES_DIR` is still
  defined in `platformio.ini` (deliverable 3 names it), and `.gitattributes` still holds
  `tests/fixtures/contracts-ahead/*.json -text` for the next file. But `fake::contractAhead`
  and the four local readers are deleted, which is what their own comments said should happen
  — "this reader goes" — and what makes the grep rail true by construction rather than by
  discipline. The next task that needs one writes three lines.
- **A `CHANGELOG.md` section for v0.7.3, which the task did not ask for.** The changelog's
  third question is *did the contract fixtures' manifest commit move?* and it calls that one
  "the dangerous one", because nothing of a consumer's stops compiling when it does. It moved
  on `master` — `461469e` → `28daabd`, 79 files to 95 — in the sync commit, which wrote no
  line, and the section still said *Nothing yet*. A consumer pinning v0.7.3 would not have
  been told that the dialect moved. The section records the move, the sixteen added files, the
  six that came across byte for byte, and that no method, no constant and no existing file's
  bytes moved. `./tools/release.ps1 -Action check` is green. **If the reviewer reads this as
  the sync commit's debt and not this task's, the section is one commit to drop.**
- **No release note.** `release-notes/unreleased/62.md` is not written: nobody with a board
  sees anything. The firmware is byte-identical in behaviour — no file under `src/` or `lib/`
  changed — and `docs/release.md` says a change nobody can see writes no file. The changelog
  line above is the other of the two, and it is the right one here: the audience is a
  consumer pinning the library, not an owner.
- **Nothing is ticked in pile 1.15's `FOLLOWUPS.md`.** Its first item
  (*The fixtures of tasks 56 and 61 wait in `tests/fixtures/contracts-ahead/`*) is **done**:
  the sync ran, each file was compared byte for byte with the copied one, the tests read the
  copied tree and the waiting files are removed. The reviewer ticks it.
